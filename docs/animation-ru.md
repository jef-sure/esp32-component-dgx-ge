# DGX-GE: анимация — как работает скрипт

[English version](animation-en.md)

На этом строится почти всё движение в движке: персонаж ходит, прыгает,
бьёт, умирает, факел горит, труп разлагается. Здесь подробно, как скрипт
живёт во времени и как скрипты сменяют друг друга.

Полное описание языка `.anim` — в начале `tools/dgx_ge_anim.py`. API — в
`include/dgx_ge_anim.h`. Общая картина — в
[overview-ru.md](overview-ru.md).

## 1. Скрипт — кадры с длительностями

Скрипт — последовательность **шагов**. Шаг — это команды, а за ними **кадр**:
картинка, которую показывать столько-то миллисекунд.

```
script wave
    frame HAND_UP 200ms        # шаг 1: картинка на 200 мс
    signal 1                   # шаг 2: сначала команда,
    frame HAND_DOWN 300ms      #        потом картинка на 300 мс
    goto wave                  # и снова с начала
```

- Шаг начинается в момент, когда кончился предыдущий кадр.
- Команды шага выполняются мгновенно, по порядку, в момент начала шага.
- Затем показывается кадр шага, и следующий шаг наступит через его
  длительность.

Линейка этого скрипта, если запустить его в момент 0:

```
мс    0          200                    500         700
      │ HAND_UP  │ signal 1, HAND_DOWN   │ HAND_UP    │ signal 1, HAND_DOWN ...
```

`goto wave` выполняется в момент 500 вместе со следующим шагом: это команда
перед кадром `HAND_UP`, отдельного времени она не занимает.

Команды шага:

| команда | что делает |
| --- | --- |
| `frame P 83ms` | показывать картинку P столько-то мс; это конец шага |
| `frame P 83ms at 2,-1` | то же, картинка сдвинута от актёра вперёд и вниз |
| `dx 3`, `dy -2` | сдвинуть актёра сразу на столько точек сцены: вперёд (назад, если меньше нуля), вниз |
| `flip` | развернуться |
| `velocity 40 0` | скорость, точек сцены в секунду, x вперёд; действует до следующей команды движения |
| `accel 0 300` | ускорение, точек сцены в секунду за секунду |
| `path x: 40*t, y: g*t*t/2` | положение по формуле от времени, раздел 3 |
| `contact on`, `contact on landed`, `contact off` | искать касания местности или нет; с событием — движок сам шлёт его в момент касания, раздел 3 |
| `contact 1 below on landed off fell` | следить, касается ли маска 1 чего-то сплошного снизу (`inside`, `below`, `above`, `left`, `right`, `beside` — слева или справа, `front`, `back` по взгляду, `any`; `within 2` — не дальше стольких точек, без него 1): событие в момент, когда коснулась, и другое, когда перестала; `contact 1 off` — не следить; `… off fell first within 8` — если в начале слежения в пределах 8 точек на этой стороне ничего нет, `fell` сразу (кадр, которому нужен пол, начат над пустотой); раздел 3 |
| `masks 0 2` | какие маски столкновений активны с этого шага |
| `carry hand SWORD_3`, `carry hand none` | каким кадром с этого шага показывать то, что в точке `hand` (поза руки); `none` — его собственным; раздел 5 |
| `release grip 52, -110` | отпустить то, что в точке, с этой скоростью (x вперёд); игре — сообщение; раздел 5 |
| `tell holder drank_wine` | событие тому, кто держит этого актёра (колба выпита): передаёт игра |
| `tell cell 451, loosened, 3` | мир карты (обычно из её правил): жизни клетки карты (номер, как в `dgx_ge_cells`) — событие, её собственному параметру — значение; делает игра |
| `press 720` | кнопка в клетке карты нажата, как ногой (её связи срабатывают); делает игра |
| `clear 421` | что лежит в клетке карты, исчезает; делает игра |
| `appear KID, mouse_go, 200, 55, left` | в точке x, y появляется актёр вида (анимации пакета) и слышит событие (его матрица выбирает скрипт); где ему жить — решает игра (у PoP — в комнате игрока, у населения — в населении) |
| `appear HERB, born, x, y with g1 = xor(g1, bit(rnd(14))), hp = 3` | то же, и новый получает параметры: выражения считает тот, кто велел появиться, в момент шага; имена — параметры вида появляющегося (своего, добавленного в пак раньше или собранного вместе с ним — `Pack.add_anims`); игра вписывает их, вызвав `dgx_ge_anim_said_params(child)` в своём `say` после старта нового и до его события |
| `vanish` | актёр уходит из игры; игра убирает его |
| `hit 2 on 1 damage 3 event hurt` | что делает маска 2, встретив маску 1 другого: урон, событие ему, `recoil` — событие себе; раздел 5 |
| `set hp 3`, `add hp -1` | параметры актёра |
| `signal 3` | сообщить игре |
| `sound 1` | звук |
| `branch` | точка ветвления: здесь можно прервать скрипт (раздел 4) |
| `hold` | остановиться на последнем кадре |
| `goto имя` | продолжить с метки этого скрипта или с начала другого скрипта |

Картинка `P` — имя картинки из пакета или число. Число — номер кадра,
который игра рисует сама по своей таблице: так сделано у PoP.

**«Вперёд»** — куда смотрит неперевёрнутая картинка. После `flip` вперёд —
в другую сторону. Сторона берётся в момент каждой команды: `flip`, а за ним
`dx 3` в том же шаге сдвинут актёра уже в новую сторону.

## 2. Время реальное

Длительности кадров — это настоящие миллисекунды, а не номера кадров экрана.

У актёра хранится одно число — **момент следующего шага**. Игра каждый кадр
экрана вызывает

```c
dgx_ge_actor_advance(&actor, now_ms, say, ctx);
```

и движок вычисляет состояние актёра на «сейчас»: проходит шаги по одному,
пока момент следующего шага не окажется позже «сейчас». Никакие кадры нигде не копятся: ни в очереди, ни в памяти.

**Быстрое устройство** вызывает `advance` часто, например каждые 20 мс. За
вызов выполняется 0 или 1 шаг, каждая картинка скрипта успевает побыть на
экране.

**Медленное устройство** вызывает реже. Пусть у скрипта `wave` вызовы идут в
моменты 0 и 600. В момент 600 движок выполнит два шага: момента 200
(`signal 1`, кадр `HAND_DOWN`) и момента 500 (кадр `HAND_UP`). На экране
окажется `HAND_UP`, а `HAND_DOWN` не будет показан ни разу. Но:
- сигнал 1 придёт в игру, в своём порядке, только позже;
- путь, пройденный актёром, тот же самый.

Медленное устройство показывает меньше картинок, но персонаж за то же время
оказывается там же, где на быстром. Фиксированных тиков нет.

**Привязка ко времени жёсткая.** Состояние актёра на момент t определено
скриптом, моментом старта и событиями, а `advance` вычисляет его на «сейчас»,
сколько бы времени ни прошло. Время не теряется. Проходить при этом приходится
все шаги между прошлым вызовом и «сейчас»: их `dx` складываются в путь, `flip`
и `set` меняют состояние, точки ветвления могут сменить скрипт.

**Часы игры.** В `advance` передаётся время игры, а не настенные часы: на
паузе оно стоит, и после паузы актёр продолжает с того же места.

Долгие процессы — труп разлагается, дерево растёт — пишутся длинными шагами,
«труп 5 минут», и вычисляются за пару шагов, даже если сцену полчаса не
показывали.

## 3. Движение между шагами

`dx` и `dy` сдвигают актёра скачком, в момент шага. `velocity` и `accel`
задают **плавное** движение, оно идёт и между шагами:

```
x(t) = x0 + v·t + a·t²/2,   v(t) = v0 + a·t
```

Положение считается точно на каждый момент шага и на «сейчас» при каждом
вызове `advance`. Поэтому прыжок по параболе (`velocity 40 -200`,
`accel 0 600`) пролетает одну и ту же кривую при любой частоте вызовов.
Координаты и скорости хранятся в 1/256 точки сцены (о точках сцены — overview-ru.md, 2.5).
Каждый отрезок пути округляется до ближайшей 1/256, а не отбрасывает
остаток: иначе медленное движение отставало бы на долю за каждый вызов.
Дробная скорость (`velocity 1000 / 83, 0` — точка за тик игры с тиком
83 мс) хранится точно, а не округляется до целых точек в секунду.

`velocity` задаёт скорость заново, а не прибавляет. Остановить актёра —
`velocity 0 0` и `accel 0 0`.

### Выражения

Любое число в команде может быть выражением: числа (и дробные), `+ - * /`,
скобки, `min`, `max`, `abs`, `sin`, `cos`, `sqrt`, `exp`, `smoothstep` (0 до
0, 1 после 1, между ними плавно: s²(3−2s), начало и конец без рывка;
`path x: smoothstep(t / 0.5) * 80, y: 0` — 80 точек за полсекунды и стоит),
именованные
константы `define`, параметры актёра и его скорость в этот момент `vx`, `vy`
(точек сцены в секунду, x вперёд): `velocity vx * 0.9, -vy * 0.7` — отскок;
где он сейчас — `x`, `y` (точки сцены, x не «вперёд», а как в сцене):
`goto turn if x < 166` — развернуться, дойдя до места.

Сравнения `<`, `<=`, `>`, `>=`, `==`, `!=` и `and`, `or`, `not` дают 1 или
0, поэтому годятся и в счёт: `velocity (hp > 0) * 40, 0` — едет, пока жив.
Порядок, от слабого к сильному: `or`, `and`, `not`, сравнение, `+ -`,
`* /`. Сравнения не идут цепочкой: `0 < x < 5` — ошибка, пишется
`0 < x and x < 5`.

`and`, `or` и `c ? a : b` — ленивые, как в C: у `a and b` часть `b` не
считается, когда `a` — 0; у `a or b` — когда `a` не 0; у `c ? a : b`
считается только выбранная часть. Значение от этого не меняется, а
меняется то, что вычисление делает само: `rnd` сдвигает кубик, только
когда его часть считается. `goto strike if near and chance > rnd(255)` —
бросок только вблизи; `power > 0 ? rnd(9) : 0` — только с силой. Часть из
постоянных ассемблер решает сам: `0 and x` — 0, `1 ? a : b` — `a`.

Биты целых чисел: `&`, `|`, `%` и функции `xor(a, b)`, `bits(x)` (сколько
единиц), `bit(n)` (2ⁿ; n вне 0..30 — 0), `field(x, first, count)` (`count`
битов с бита `first`). Отрицательное число — в дополнительном коде:
`bits(-1)` = 32. Параметр хранит −32768..32767, поэтому в нём 15 битов
(0..32767), отрицание этих битов — `xor(x, 32767)`. Например, гены в двух
параметрах: родство с партнёром, чьи гены скопированы в `mate_g1`, — `bits(xor(g1, mate_g1))`, мутация —
`xor(g1, bit(rnd(14)))`, черта — `field(g1, 4, 3)`.

Таблица констант — числа, которые формулой не выразить, по номеру:

```
table strike_chance 75 100 75 75 75 50 100 220 0 60 30 255
param skill 0

script guard_think
    goto strike if strike_chance[skill] > rnd(255)
```

Таблица объявляется до того, как её читают; значения — постоянные,
−32768..32767. Номер — целая часть выражения, вне таблицы — 0. С
постоянным номером ассемблер подставляет число сразу. Таблицы лежат в
блобе анимации после её кода и ничего не стоят актёру; в плитках их нет.

Вопрос к игре — то, что знает только она (расстояние по её правилам, видит
ли один другого, есть ли впереди пол):

```
game distance sees                 # вопросы по порядку: distance 0, sees 1

script think
    goto calm if game.sees == 0
    goto strike if game.distance < 29 and strike_chance[skill] > rnd(255)
```

`game.<имя>` — ответ игры в момент шага: игра ставит свою функцию
`dgx_ge_expr_ask(номер, контекст)` и контекст `dgx_ge_expr_ask_ctx`; нет
функции — 0. Имена объявляются до чтения, номера в заголовке пакета —
`<PREFIX>_<АНИМАЦИЯ>_GAME_<ИМЯ>`. Актёру это ничего не стоит. В `path` и
в плитках вопросов нет: путь считается по одному `t`. `rnd` бросается
только на шаге, который выполнился и в той части выражения, которая
считается (`and`, `or`, `?:` ленивые), поэтому кубик бросается ровно на
выбранной дороге.

Ось геймпада игрока — `axis(<имя>)`: стики `lx`, `ly`, `rx`, `ry` от −1
до 1, курки `lt`, `rt` от 0 до 1, такие, какие они в момент шага:

```
script walk
    velocity axis(lx) * 120, 0      # наклон — скорость (с выражениями — через запятую)
    frame WALK_1 83ms
    goto walk
```

Какой ввод читают скрипты, игра говорит один раз: `dgx_ge_expr_input =
&input` (`include/dgx_ge_input.h`, мёртвая зона уже снята); нет ввода — 0.
Только в скриптах анимаций: не в `path` (путь считается по одному `t`), не в
плитках (клетка перекладывается, только когда сменилась, и стик был бы
виден таким, каким был тогда) и не в условиях диалогов.

Тот же язык — в плитках (overview-ru.md, 2.6): там имена — модификатор
клетки `mod`, её вариант `variant` и их поля по именам набора плиток.

```
define gravity 432
define tick 1000 / 12
param power 200

script throw
    velocity 40, -power        # с выражениями операнды разделяются запятой
    accel 0 gravity
    frame STONE tick
```

Выражение из одних чисел и констант ассемблер вычисляет сразу, и на плате
оно ничего не стоит. С параметрами — вычисляется в момент шага:
`velocity`, `accel`, `set`, `add` (и в `path`). Длительность кадра, `dx`,
`dy`, `at`, `signal`, `sound`, `masks` — только постоянные.

Числа, общие для всей игры, текст пишет именами, а числами их делает
упаковщик. Маску там, где её ждут (`masks`, `hit … on …`, `contact`),
называют по имени — тому же, что в `meets` и в заголовке: `masks BODY
TIP`, `hit TIP on BODY damage 1`; число тоже годится. Свои числа игра даёт
упаковщику константами (`Pack.add_constants(TICK_MS=83, TILE_FLOOR=2)`, в
файле редактора — поле `constants`): их имена стоят везде, где может
стоять число, как свои `define` (`define tick 1000 / TICK_MS`,
`signal CLOCK_OUT`). Переопределить такое имя своим `define` нельзя.

### `path` — положение по формуле

```
path x: 40*t, y: -power*t + gravity*t*t/2     # бросок
path x: 0, y: 3*sin(t*6)                      # покачивается на месте
path x: min(t, 0.5)*80, y: 0                  # проехал 40 точек и встал
```

- `t` — секунды с начала `path`. Положение актёра — точка, где начался
  `path`, плюс формула; x — вперёд, с учётом стороны в момент начала.
- Действует, пока его не сменит другая команда движения: `path`,
  `velocity` или `accel`. Смена кадров и скриптов его не прерывает. После
  смены актёр продолжает со скоростью, которая была у формулы.
- `dx` и `dy` во время `path` сдвигают его начало.
- Положение на любой момент вычисляется прямо по формуле — привязка ко
  времени точная, без перебора и без накопления ошибки.
- Скорость актёра (её может читать игра) — производная формулы в этот
  момент.
- Параметры в формуле читаются при каждом вычислении: игра может менять
  движение на ходу, меняя параметр.
- `vx` и `vy` в формуле пути нельзя: скорость даёт сама формула, и чтение
  своей прошлой скорости сделало бы место зависимым от частоты кадров.

Цена: формула вычисляется на плате при каждом `advance` актёра, стоящего на
`path`, во float; у ESP32 плавающая точка аппаратная. Стек вычислителя —
16 значений, выражение — до 255 байт.

### Касание местности

Местность — то сплошное в сцене, чего касаются актёры: полы, стены,
бамперы. Движок её не знает, её описывает игра (потом — модуль плиток)
двумя функциями в `dgx_ge_terrain_t`: «касается ли тело актёра, поставленное
сюда, чего-то сплошного» и «что делать при касании». Актёру местность
задаёт игра (`actor.terrain`), искать касания велит скрипт:

```
script fly
    contact on          # искать касания; contact off — перестать
    accel 0 gravity
label flying
    frame BALL 1000ms
    goto flying
```

- **Где движок смотрит.** На границах шагов скрипта и на «сейчас». Было
  снаружи, стало внутри — касание где-то между. Касание считается только при
  входе: пока актёр остаётся внутри, повторно не сообщается.
- **Что решает игра.** Её функция получает касание: отрезок времени, где оно
  случилось, примерное место, нормаль поверхности, что задето. Решить можно
  что угодно: отскочить (мяч), погасить скорость (мягкий пол), добавить
  (бампер пинбола), пройти насквозь, послать событие матрице.
- **Событие вместо кода.** `contact on landed` — движок сам уточняет
  момент касания, ставит актёра туда и шлёт ему `landed` в этот момент;
  что дальше, решает матрица его вида: колба — `flying -> shatter`, камень
  — `flying -> lying`. Новый скрипт сам задаёт движение (`velocity 0 0`).
  Функция игры, если есть, вызывается раньше; если она сама переставила
  актёра (отскок), событие не шлётся.
- **Точно, если нужно.** Внутри отрезка шагов нет, движение непрерывное, и
  `dgx_ge_actor_state_at()` даёт состояние на любой его момент.
  `dgx_ge_contact_refine()` уточняет момент касания делением пополам до
  миллисекунды; можно и решить уравнение самой игре. `dgx_ge_actor_restart()`
  ставит актёра в точный момент касания с новой скоростью, и движок
  продолжает от него до «сейчас». Так мяч скачет одинаково при любой
  частоте кадров.
- **Касание масками.** `contact on` смотрит на точку-основание актёра.
  `contact 1 below on landed off fell` следит за маской: касается ли она
  чего-то сплошного с этой стороны (пол под ногами — снизу, стена впереди
  — `front`, потолок — сверху, вода — `inside`), не дальше `within N` точек.
  Коснулась — первое событие, перестала (пол кончился) — второе, каждое в
  точный момент: движок находит его между двумя взглядами делением
  пополам, ставит актёра туда и шлёт событие; дальше решает матрица.
  Маска целиком внутри сплошного (внутри, и ни одной стороны в пределах
  `within`) касается его с любой стороны: шаг, унёсший её сквозь край
  (быстро, или край тонкий), — тоже касание, с первой его миллисекунды
  (ноги, влетевшие в плиту пола, приземлились на неё). Маска, вошедшая
  частью, касается с тех сторон, с которых её точки снаружи видят
  сплошное (край, который она пересекла): `front` не сработает на стене
  за спиной, в которую залез край картинки; `within 0` видит только
  «внутри» — тогда любая сторона считается.
  Покой событий не даёт: стоишь на полу — ничего не приходит. Кто
  отвечает, касается ли маска здесь, — местность игры
  (`dgx_ge_terrain_t.sides`); сетка плиток и реестр тел дают готовые
  ответы (`dgx_ge_grid_touch_sides`, `dgx_ge_collisions_touch_sides`), а
  «чем и чего касается сейчас» игра спрашивает сама, когда нужно
  (`dgx_ge_grid_touching`, `dgx_ge_collisions_touching`: маска, сторона,
  область, что встречено). Следить можно за `DGX_GE_ANIM_CONTACTS` (2)
  масками сразу.
- **Луч.** `dgx_ge_terrain_ray()` — первое сплошное на отрезке от точки до
  точки: видит ли стражник принца, куда попадёт выстрел, не проскочил ли
  быстрый снаряд стену. Местность может дать свой точный луч (сетка плиток —
  по клеткам), иначе движок идёт по отрезку шагами и уточняет место
  попадания до точки.

> **Внимание: тонкие стены.** Движок смотрит касания только на границах
> шагов и на «сейчас». Если между двумя такими моментами актёр проходит
> больше, чем толщина стены, касания он не заметит и пройдёт насквозь. Это
> ошибка разработчика игры, не движка. Как не допустить:
> - **делать шаги короче:** быстрый актёр — кадры по 20–40 мс, а не по
>   секунде, чтобы между проверками он сдвигался меньше толщины стены;
> - **не делать стен тоньше пути** самого быстрого актёра за один шаг;
> - **проверять путь лучом:** для пули или камня — `dgx_ge_terrain_ray()`
>   от прошлого места до нового в функции касания или в коде игры.

Так сделан мяч в комнате Prince of Persia: скачет, ложится, катится с
постоянным замедлением и останавливается в рассчитанный момент, с края
падает, от стены отскакивает.

### Восприятие: `sense`

`sense` — шаг «найди ближайшего и запиши, где он»: актёра названного вида,
кого угодно (`any`) или клетку сетки (`cell`), в радиусе, по условию:

```
param hp 3
param age 0
param sex 0
param enemy 0
param edx 0
param mate 0
param food 0

script graze
    sense WOLF within 80 into enemy, edx       # волк ближе 80 точек: расстояние, x вперёд
    goto flee if enemy >= 0 and enemy < 50
    sense HERB within 60 where its.sex != sex and its.age > 3 into mate
    sense cell within 30 where its.mod >= 2 into _, _, _, food = its.cell
    frame GRAZE 200ms
    goto graze

script flee
    frame RUN 100ms
    goto graze
```

- Радиус — число или выражение своего актёра, считается в момент шага:
  `sense SHEEP within 30 - full / 4 into d` — голодный волк чует дальше
  (меньше 0 — 0). Так же чутьё из генов.
- `seen` после радиуса — только тот, кого видно: путь взгляда до него
  стоит не больше радиуса, а цену назначает местность по завесе плиток
  (`veil` тайла: 0 прозрачно, 1..6 — точка сквозь неё стоит 2..7, 7 — не
  видно насквозь). `sense SHEEP within 120 seen into d` — глаз волка: овцу в
  кусте он не видит, в лесу видит ближе. Без `seen` — нос: чует сквозь всё.
  Клетку при `seen` видно саму, её собственная завеса не считается.
- `into d, dx, dy` — расстояние (точки, округлённое; −1 — никого), смещение
  до найденного: x вперёд (как у `velocity`), y вниз. Лишние с конца можно
  не писать, ненужное в середине — `_`. Никого: d = −1, dx = dy = 0.
- Дальше — копии: `<параметр> = <выражение>`, в котором `its.` — найденный.
  Так в себя переписывают то, что понадобится потом: гены партнёра,
  номер клетки травы. Никого не нашлось — копии не трогаются.
- `where` — условие, которое найденный должен выполнить; проверяется во
  время поиска, так что ближний неподходящий не заслоняет подходящего
  дальше.
- `its.<параметр>` — параметр найденного по нумерации его вида, поэтому
  только при названном виде (свой вид — свои параметры, чужой — из видов,
  добавленных в пак раньше). У актёра ещё `its.vx`, `its.vy` (его скорость,
  x вперёд от ищущего), `its.image`, `its.script`, `its.flip`; у клетки —
  `its.tile`, `its.mod`, `its.cell` (номер клетки игры, для `tell cell`).

Кого видно, решает игра: у местности актёра крючок `sense`, ответы на него
дают `dgx_ge_sense_bodies` (реестр тел: тела, у которых игра указала актёра,
`dgx_ge_collisions_actor`; вид известен у анимаций, открытых через
`dgx_ge_kind`) и `dgx_ge_sense_cells` (сетка: непустые клетки). Игра
соединяет их и даёт клетке свой номер. Без крючка `sense` никого не
находит. Ищется в момент шага, по тому, где тела стоят в реестре.

### Руление: `steer`

`steer` задаёт скорость по Рейнольдсу (steering behaviors): желаемая
скорость по виду, к ней — не больше чем на «силу» за шаг, и не быстрее
«скорости». Цель обычно — то, что нашёл `sense`; оси — x вперёд.

```
script flee
    sense WOLF within 120 into enemy, edx, edy
    goto graze if enemy < 0
    steer flee speed, 40 from edx, edy        # от волка; скорость — параметр (из генов)
    frame RUN 83ms
    goto flee
```

| Запись | Желаемая скорость |
|---|---|
| `steer seek <скорость>, <сила> to <dx>, <dy>` | к цели, на полной |
| `steer flee <скорость>, <сила> from <dx>, <dy>` | от цели, на полной |
| `steer arrive <скорость>, <сила>, <радиус> to <dx>, <dy>` | к цели; внутри радиуса — пропорционально расстоянию, у цели 0 |
| `steer pursue <скорость>, <сила> to <dx>, <dy>, <vx>, <vy>` | к месту, где цель будет: через расстояние / скорость при её скорости vx, vy |
| `steer evade <скорость>, <сила> from <dx>, <dy>, <vx>, <vy>` | от этого места |
| `steer wander <скорость>, <сила>, <разброс> angle <параметр>` | по углу (градусы, 0 — вперёд, 90 — вниз), который каждый шаг сдвигается на случайное в ± разброс (кости игры) |

- **Сила** — на сколько точек в секунду скорость может измениться за один
  `steer`, не ускорение: при шаге раз в 83 мс поворотливость 700 точек/с²
  — это сила 58. Большая сила — поворот сразу, маленькая — плавная дуга.
- Скорость держится до следующего шага; ускорение `steer` обнуляет, `path`
  снимает. Между шагами движение прямое, касания ищутся как обычно.
- Цель в нуле (`sense` никого не нашёл, dx = dy = 0) — желаемая скорость 0,
  актёр тормозит.
- Все операнды — выражения.

## 4. Смена скриптов: события и матрица

Скрипт сам не решает, когда смениться на другой, если только не дошёл до
`goto`. Смену вызывает **событие**: игра решила, что пора, и посылает

```c
dgx_ge_actor_event(&actor, EVENT_JUMP, now_ms, say, ctx);
```

Что из события следует, говорит **матрица** «скрипт × событие». Строка
матрицы — скрипт, в котором актёр сейчас. В клетке — куда перейти и
**когда**:

| когда | что значит |
| --- | --- |
| `now` | сразу: текущий кадр обрывается, новый скрипт начинается в этот момент |
| `branch` | в ближайшей точке `branch` текущего скрипта или в его конце |
| `end` | когда текущий скрипт дойдёт до конца |

**Конец скрипта** — место, где он пошёл бы в другой скрипт или
остановился: `goto` (даже на метку внутри себя, то есть конец круга
цикла) или `hold`.

Пустая клетка — событие здесь ничего не делает, и `dgx_ge_actor_event`
вернёт false.

Правила, которые заполняют клетки:

```
group ground: stand, run
on jump: ground -> leap now
on stop: run -> stand branch
on land: fall -> stand end
```

Порядок правил ничего не значит, приоритетов нет, два разных ответа на одну
клетку — ошибка сборки.

### Пример: бег прерывается в точке ветвления

```
script run
    frame RUN_1 80ms
    dx 4
    frame RUN_2 80ms
    branch
    dx 4
    frame RUN_3 80ms
    goto run
```

Актёр запущен в `run` в момент 0, событие `stop` с ответом
`run -> stand branch` пришло в момент 100:

```
мс    0        80         160                       ...
      │ RUN_1  │ dx 4,    │ branch: ждущий переход
      │        │ RUN_2    │ взят, дальше stand
              ↑
              100: stop — запомнен, ждёт точки ветвления
```

Если бы `stop` пришёл в момент 170, точка ветвления уже прошла бы, и
переход случился бы в конце круга, на `goto run` в момент 240.

### Тонкости

- **Ждущий переход один.** Пришло ещё одно событие с ответом `branch` или
  `end` — оно заменит ждущее.
- **Ответ `now` сначала вычисляет состояние на момент события.** Движок
  проходит шаги, которые уже наступили, затем входит в новый скрипт в
  момент события и сразу выполняет его первый шаг. Поэтому кадр нового
  скрипта виден в том же кадре экрана.
- **Остановленный актёр** (`hold`) отвечает на любое событие сразу, даже с
  ответом `branch` или `end`: ждать ему больше нечего.
- **Строка матрицы меняется только при входе в скрипт:** при старте, по
  событию или по `goto` на другой скрипт. Метка — не скрипт: `goto` на
  метку оставляет актёра в той же строке.
- **Скрипт без `goto` или `hold` в конце** продолжается в следующий по
  тексту, но строка матрицы остаётся прежней. Почти всегда это ошибка;
  редактор предупреждает. Заканчивайте скрипт `goto` или `hold`.

## 5. Что скрипт сообщает игре

`signal N` и `sound N` вызывают функцию `say`, которую игра передала в
`advance` и `event`:

```c
static void say(dgx_ge_actor_t *actor, dgx_ge_anim_say_t what, uint8_t value, uint32_t at_ms, void *ctx)
{
    if (what == DGX_GE_ANIM_SIGNAL && value == SIGNAL_FOOT_DOWN) ...
    if (what == DGX_GE_ANIM_SOUND && now_ms - at_ms < 100) play(value);   /* давний звук не играть */
}
```

`at_ms` — момент шага, которому принадлежит сигнал.

### Что в руке: `carry`

Точка привязки кадра (`hand`) говорит, где держат; что держат, говорит
скрипт: `carry hand SWORD_3` — с этого шага в руке эта картинка, `carry hand
none` — ничего. Действует до следующего `carry` той же точки, как `masks`.
Меч на замахе и на ударе — разные кадры меча, и скрипт меняет их вместе с
кадрами тела. У актёра две такие ячейки (`DGX_GE_ANIM_CARRIED`): меч и
щит.

Игра берёт картинку `dgx_ge_actor_carried(актёр, точка)` и вешает её в
точку кадра тела (`dgx_ge_item_held`, `include/dgx_ge_scene.h`). Показывать
ли её вообще (вынут ли меч), решает игра.

У каждого персонажа свои скрипты, если у них разные картинки: у PoP принц и
стражник ходят по одной таблице оригинала, но держат в одних и тех же
кадрах разные кадры меча. Конвертер делает из неё два набора, `kid.anim` и
`guard.anim`, с одинаковой нумерацией скриптов и событий.

### Предмет в руке — актёр

То, что держат, может быть актёром со своими скриптами: меч, колба,
камень. Что он такое (маски, `hit`, состояния), говорит его вид; как его
держат — носитель. `dgx_ge_actor_hold(носитель, точка, предмет)` кладёт
его в руку; `carry` носителя задаёт кадр по позе руки
(`dgx_ge_held_image`: кадр позы, иначе собственный кадр предмета).
Активны у предмета в руке маски, активные и у него, и у носителя
(`dgx_ge_held_masks`): на замахе острие не опасно. `release` отпускает
предмет: он свободен и летит со скоростью броска с момента шага;
`dgx_ge_actor_drop` — выпал без броска.

### Взять и бросить: игра кладёт, скрипт отпускает

Что подобрано, знает игра: принц присел над зельем, и игра кладёт колбу в
руку — `dgx_ge_actor_carry(актёр, точка, картинка)`, ту же ячейку, что
заполняет `carry`. Отпускает скрипт, в свой момент движения:

```
script throwpotion
    frame 229 83ms        # поднялся с колбой
    frame 230 83ms
    frame 231 83ms        # рука вперёд
    release grip 52, -110 # отпустил: 52 вперёд, 110 вверх, точек в секунду
    frame 232 83ms
```

`release <точка> [vx vy]` освобождает ячейку и сообщает игре
(`DGX_GE_ANIM_RELEASE`, значение — номер точки) с моментом шага. Что
отпущено и как быстро, лежит в `actor->released` (картинка, vx уже со
стороной актёра, vy). Скорости — выражения, как у `velocity`; не заданы —
0 0. В руке ничего нет — ничего и не происходит. Из отпущенного игра
делает что хочет: летящую колбу, брошенный камень. Где была рука, она
находит по точке кадра в момент шага.

### Карманы: `draw`, `stow`, `count`, `goto … if`

Кроме рук у персонажа бывают карманы (`dgx_ge_pockets.h`): меч в ножнах,
кинжалы за поясом, зелье. Сколько мест — объявление его анимации, сколько
вещей одного вида ложится в одно место — объявление анимации вида вещи;
хранит ли мир брошенную вещь — шаг `keep` в скрипте её состояния:

```
pockets 6          # у персонажа: шесть мест
stack 10           # у вида «кинжал»: до десяти в одном месте

script lying       # у кинжала
    keep           # лежащий мир хранит, новым не уступает (осколки колбы — нет)
```

Вид вещи — её анимация в пакете (номер блоба ставит упаковщик, как у
`shoot`). Скрипты носителя достают и убирают вещи в момент движения:

```
script engarde
    draw hand SWORD          # меч из ножен в руку (нет меча — ничего)
    ...
script resheathe
    ...
    stow hand                # что в руке — в карман
script throwdagger
    goto stand if count(DAGGER) == 0   # нечего метать — стоять
    shoot hand DAGGER 220 0            # кинжал берётся из кармана
```

- `draw <точка> <вид>` — одна вещь вида из карманов в руку: актёр
  карманов (по одному на точку, `DGX_GE_ANIM_CARRIED`), в том скрипте и с
  теми параметрами, с какими её убрали. Рука занята или вещи нет —
  ничего.
- `stow <точка>` — что в руке, в карман (запись 8 байт: вид, скрипт,
  параметры, сколько). В стопку ложатся только одинаковые: отравленный
  кинжал не ляжет к простым. Не влезло — остаётся в руке.
- `shoot` у того, у кого есть карманы, берёт снаряд из них; нет — нет и
  выстрела. Без карманов — как прежде.
- `count(ВИД)` в выражениях — сколько вещей вида в карманах; `goto <метка
  или скрипт> if <выражение>` — переход, когда выражение не 0 (как
  `goto`: переход, ждущий конца, берётся здесь).

Карманы актёру даёт игра после старта (`actor->pockets`); перечислить,
проверить, влезет ли, переложить из одних в другие, выложить в мир —
`dgx_ge_pockets_*`.

Выложенное ложится стопкой к таким же, рядом с другими или в кучу
(`dgx_ge_world_lay`). Сколько лежит в стопке, актёр знает (`amount`), и
кадр может от этого зависеть — кадр выражением, в скобках, картинки
пакета в нём — имена:

```
script lying
    frame (DAGGERS_1 + min(amount, 10) - 1) 1000ms
```

### Удар: `hit`

Урон — свойство не бойца, а удара: тычок снимает меньше апперкота,
подсечка роняет. Поэтому удар описывается в скрипте, на шагах удара, рядом
с масками:

```
script strike
    masks BODY TIP
    hit TIP on BLADE recoil parried   # острие о клинок: ударивший получает parried
    frame STRIKE_1 83ms
    hit TIP on BODY damage 1          # острие на теле: урон 1
    hit TIP on BLADE recoil parried
    frame STRIKE_2 83ms
    masks BODY                        # удар кончился
```

- События — имена пакета: один номер для всех видов (упаковщик), так что
  `event taken` у руки принца — то же `taken`, что в матрице колбы. Имя,
  названное в `hit`, объявлять не надо; реагирует на него тот вид, который
  объявил его у себя.
- `hit <маска> on <маски>` — что делает своя маска, встретив эти маски
  другого (`on BODY SHIELD` — тело или щит). Дальше по желанию: `damage N` — урон,
  `event e` — событие тому, кого встретили, `recoil e` — событие себе
  (отскок от блока).
- Строки `hit` подряд идут вместе. Они действуют, пока не сменятся
  следующими `hit`, командой `masks` или другим скриптом: удар — часть
  движения, где он написан.
- Встречу масок находит `dgx_ge_collisions_look` (столкновения,
  overview-ru.md, 2.8). Игра спрашивает `dgx_ge_actor_hit(актёр, своя маска,
  маска другого, &hit)` и шлёт события сама. Что событие значит, решает
  матрица того, кто его получил: один и тот же удар в стойке — ранение, в
  блоке — отшатывание, по лежащему — ничего.
- Урон снимает игра, по своим правилам: полный, частичный в блоке, со
  снижением в серии. Движок урон только передаёт.

В PoP так описан бой: у картинки меча две маски — острие (`TIP`) и весь клинок
(`BLADE`). На кадрах удара острие, встретившее клинок парирующего, отбито; на
последнем кадре острие на теле ранит. Номеров кадров в коде боя больше нет.
Что игра делает дальше (минус жизнь, смерть, падение с края, отбивший
держит клинок), — её правила.

Сигнал — момент, который важен логике игры: нога коснулась пола, рука
отпустила камень, персонаж поднялся на ряд выше. Что значит число, решает
игра. Сигналы приходят в порядке шагов. На медленном устройстве или после
долгого перерыва они приходят позже своего момента, но не теряются, и по
`at_ms` видно, когда они должны были случиться.

## 6. Параметры

Параметры — числа, которые каждый актёр хранит у себя: жизни, «что он
делает».

```
param hp 3          # объявлен до первого использования, начальное значение 3
param action 0

script drink
    add hp 1
    frame DRINK_1 100ms
    ...
```

- При `dgx_ge_actor_start` параметры получают начальные значения.
- Скрипт изменил параметр (`set`, `add`), и значение стало другим —
  игре сообщается `DGX_GE_ANIM_PARAM` с номером параметра и моментом шага:
  там она меняет то, чего скрипты не знают (палитру мира при опьянении).
- В выражениях `now` — момент шага в секундах часов игры: `set drunk now +
  10` — «пьян до такой-то секунды».
- При смене скриптов они сохраняются.
- `add` упирается в границы 16 бит, а не переполняется.
- Игра читает их по номерам из заголовка пакета:
  `actor.params[MYGAME_HERO_PARAM_HP]`.

Движок не знает, что значат параметры, и не проверяет порогов. «Жизни
кончились» решает игра и посылает событие.

---

## 7. Что такое кадр для игры

Скрипт задаёт только номер картинки, её сдвиг от актёра (`at dx,dy`) и
сторону (`flip`). Актёр — не элемент сцены. Каждый кадр экрана игра сама
делает из него элемент сцены (`dgx_ge_item_t`): берёт картинку по номеру,
ставит её по месту актёра и сдвигу, отражает, выбирает слой и ключ. Так
одна и та же анимация может рисоваться по-разному: у PoP номер кадра
сначала ищется в таблице кадров игры, а у стражника в другой таблице, чем
у принца.
